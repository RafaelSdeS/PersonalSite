# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A static, no-build personal portfolio site (in Portuguese, "SitePessoal"). Plain HTML/CSS with a small inline vanilla-JS theme toggle (no package manager, no build step). Hosted via GitHub Pages (see CNAME history in git log).

## Running locally

There is no build/test/lint tooling. Open the HTML files directly in a browser, or use the VS Code "Live Server" extension (`.vscode/settings.json` sets its port to 5503) for auto-reload while editing.

## Architecture

- `index.html` — **English homepage, the default/primary version.**
- `indexpt.html` — Portuguese translation of the same page. **Both files share identical structure, section IDs, and classes** — they are kept in sync manually. Any structural or styling change to one almost always needs the same change in the other; only the text content and the `.lang` language-toggle link differ (`index.html` links to `indexpt.html` and vice versa).
- `style.css` — base styles, reset, design tokens and every component. Colors/fonts are CSS custom properties in `:root` (`--bg`, `--tile`, `--border`, `--border-hi`, `--text`, `--muted`, `--faint`, `--accent`, `--on-accent`, `--header-bg`, `--sans` Space Grotesk, `--mono` JetBrains Mono) — change a token rather than hardcoding values. Dark theme is the default. Light-mode token values are duplicated in two places: a `@media (prefers-color-scheme: light)` block (guarded by `:root:not([data-theme="dark"])` so an explicit manual choice can override system preference) and a `:root[data-theme="light"]` block for the manual toggle. `.theme-toggle` (in the sticky `.top` header, both pages) calls the inline `toggleTheme()` defined in each page's `<head>`, which flips `data-theme` on `<html>` and persists it to `localStorage`; the same head script re-applies the stored choice before first paint. A second inline script at the end of `<body>` adds `.scrolled` to the header, sets the reading-progress `--p` on it, highlights the nav link of the section in view pins the other cards of a row to their height while one card's `details` is open (so only that card grows), and wires the copy-email button (`data-copy` / `data-done` hold the per-language text, so the script stays identical; hidden without the Clipboard API). Keep both scripts identical across `index.html`/`indexpt.html`.
- Motion layer (end of `style.css`, `/* MOTION */`): the head script adds `.motion` to `<html>` unless `prefers-reduced-motion` is set; only then do `main`'s direct children start hidden and rise in once via an IntersectionObserver in the body script (`.in` + stagger `--d`; the animation uses `backwards` fill so `:hover` transforms still work afterwards). The body script also writes the pointer position `--mx/--my` on the hovered `.tile` for the accent spotlight (`@property --spot`). `toggleTheme()` uses `document.startViewTransition` (when available and `.motion` is on) for a circular wipe from the toggle (`--vx/--vy`). `media.css` disables all transitions/animations under reduced motion and forces revealed tiles visible in print.
- `media.css` — all responsive overrides, loaded after `style.css`. Breakpoints: `max-width: 1080px` (tablet: tiles full width, project tiles pair up, intro/about stay 8 + portrait/photo 4), `680px` (phone: one column), `540px` (nav links hidden, header actions stay; the PT nav needs ~530px). Keep breakpoint-specific rules here.
- `assets/images/` — `rafael-portrait.jpg` (hero), `ufrgsmun-rafael.jpg` (next to Background, no caption on purpose — a Rafael-only 4:5 crop of `_DSC0863.jpg`, the in-focus shot, cut above the country placard so it doesn't read as an event photo; he faces left, so it sits right of the text), `ufrgsmun-press.jpg` (3:2 figure of the Activities card: Rafael speaking at the press interview), `ufrgsmun-committee.jpg` (the whole committee holding placards, shown inside that card's `details` — a `details` may hold one photo, wrapped in `<div class="pic">` so it zooms on hover inside its frame), `nasa-space-apps-certificate.jpg` (linked only from the LUNAX sublinks) and `projects/*.webp` (one 3:2 figure per tile: real screenshots, figures from the user's slides, or renders), plus `og-en.jpg` / `og-pt.jpg` (1200×630 link-preview cards). Two figures (Quant, File Organizer) are inline SVG diagrams in the HTML, styled by `.diagram` in `style.css` — schematic only, never invented data.
- `assets/docs/voris-report.pdf` — the VORIS research report, linked from that card's sublinks. Built from the LaTeX source (abnTeX2) and compressed with `gs -sDEVICE=pdfwrite -dPDFSETTINGS=/ebook` (18.5 MB → ~0.6 MB); this machine's TeX lacks babel-portuges and cm-super, so the build used a CTAN copy of babel-portuges via `TEXINPUTS` and `\usepackage{lmodern}` in a scratch copy of the source.
- `assets/icons/` — a custom icon font (generated via IcoMoon, per `assets/icons/Read Me.txt`) with its own `style.css`, `fonts/`, and `selection.json` (reimport into icomoon.io to change icons; don't hand-edit the font). Covers `icon-gmail`, `icon-github`. LinkedIn has no glyph, so the contact tile uses an inline SVG.
- `variants/` — untracked design prototypes (Split, Bento preview) kept locally; not part of the site.
- `<head>` of both pages (public URL `https://rafaelsdes.github.io/PersonalSite/`, GitHub Pages from `main`): absolute canonical / `og:url` / `hreflang` (+ `x-default` → EN), `og:image` = that language's card, `twitter:card`, `favicon.svg` + `apple-touch-icon.png` (root), and an identical JSON-LD `Person` block — facts only from the site. The résumés link the favicon too.
- `tools/og-card.html` — template for the link-preview cards (EN by default, `?lang=pt` for PT; texts mirror the hero). Regenerate after changing the hero or portrait: `chromium-browser --headless --hide-scrollbars --virtual-time-budget=3000 --window-size=1200,630 --screenshot="$PWD/og-en.png" "file://$PWD/tools/og-card.html"` (and `?lang=pt` → `og-pt.png`), then save each as `assets/images/og-*.jpg` (JPEG q85) and delete the PNGs. `apple-touch-icon.png` is `favicon.svg` rendered the same way at 180×180 with `--default-background-color=0e0f11ff`.

- `resume.html` / `resumept.html` + `resume.css` — one-page printable résumé (EN/PT), linked from the `CV` pill in each page's `.header-actions`. Deliberately standalone (does not load `style.css`): white, single column, semantic `h2`/`h3`/`ul` for ATS/AI parsing, must print to exactly 1 page (Letter and A4). It restates the site's facts in condensed form — when a project/experience changes on the site, update both résumés too. Each résumé's `.actions` bar offers `resume.pdf` / `resumept.pdf` (`download` names them `Rafael-Silva-de-Souza-CV.pdf` / `-Curriculo.pdf`); **regenerate both PDFs whenever a résumé changes**: `chromium-browser --headless --no-pdf-header-footer --print-to-pdf="$PWD/resume.pdf" "file://$PWD/resume.html"` (same for `resumept`), and check `pdfinfo` reports `Pages: 1`.

Both HTML pages use one 12-column "bento" grid (`main.bento`, tiles `.tile` sized with `.s4/.s6/.s8/.s12`; section headings are `h2.group` — big title plus an accent-led hairline — and tile titles are `h3`), in this order: intro (`.intro`) + portrait → `#work` group ("Current work": Research + Quant tiles, then the `.focus` strip) → Background (`.about`, s8) + photo (`.photo`, s4) → `#experience` (VORIS + E3) → `#projects` (six project tiles) → `#activities` (one UFRGSMUN card, `.tile.s12.p.wide`: the same card shape, but the figure sits left of a `<div>` holding label → desc, and `details` + `.tags` span the full width below; inside `details`, `.cols` repeats the split — the extra photo left, a `<div>` with both texts right — so the open card stays balanced; one column on phones) → `#contact` (full-width skills tile with groups in two columns, then a full-width `.contact` band: `.pitch` on the left, link rows on the right with a copy-email `.pill.copy`) → `footer.credit`. Work, experience and project tiles share one shape (`.tile.p`): `a.shot-link` figure (links to the live demo when there is one, else the title link) → `.label` → `.hl` headline → `.metric-label` facts line → `h3` title link → optional `.sublinks` → `.desc` → `details` ("How I contributed / What I learned") → `.tags`. Keep that shape on every card. Headlines state what the project shows; never replace them with bare "effect numbers". The sticky `.top` header holds the section nav, the theme toggle and the CV / language pills (`index.html` → `resume.html` + `indexpt.html`; `indexpt.html` → `resumept.html` + `index.html`).
